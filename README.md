# CivicEye — Smart City Problem Reporter

A responsive, multilingual civic issue reporting web app built with HTML, CSS, vanilla JavaScript, Node.js/Express and SQLite.

## Features
- Responsive home page and issue reporting form
- English, Tamil and Telugu interface
- Pothole, garbage, streetlight, water, drainage and other categories
- Location entry and optional device geolocation (browser permission required)
- Optional JPG/PNG/WebP image upload (3 MB maximum)
- Server-side SQLite persistence, reference IDs, report filters and status statistics
- Admin login, mark resolved/reopen, delete report controls
- Password hashing, session cookies, rate limits, security headers, input limits and same-origin checks

## Run on Windows (one-time setup)
1. Install Node.js 20 or newer from https://nodejs.org/.
2. Extract this ZIP and open the `CivicEye_FullStack` folder.
3. Copy `.env.example` and rename the copy to `.env`.
4. Open `.env` and set a private admin username, a strong admin password and a random `SESSION_SECRET` of at least 32 characters.
5. Open Terminal in this folder and run `npm install`.
6. Run `npm start` and open http://localhost:3000.

## Admin dashboard
Open the site, choose **Admin dashboard**, then sign in with the values you set in `.env`. For a fresh local install only, if you have not set `.env`, the fallback username is `admin` and password is `ChangeThisPassword123!`. Change this before using the app beyond local testing.

## Data and deployment notes
- Reports and uploaded photos are stored in `data/` and `uploads/` on the server.
- Back up both folders. Use a host with persistent disk storage; ephemeral serverless filesystems will lose data.
- For production, set `NODE_ENV=production`, set a strong random `SESSION_SECRET`, use HTTPS, configure persistent storage and backups, and change the default admin credentials.
- This project records reports; it does **not** automatically send them to municipal authorities. A real civic service needs an agreed integration/workflow with the relevant authority, plus privacy and abuse-reporting policies.
- I can provide the project files here, but public deployment requires a hosting account and its deployment authorization. This package is not represented as already published online.


## Deploy online (Render)
1. Upload the contents of this folder to a new GitHub repository (do not upload `node_modules`, `.env`, or personal secrets).
2. In Render, choose **New + → Blueprint**, connect that GitHub repository, and select the `render.yaml` file.
3. When prompted, set a strong unique `ADMIN_PASSWORD`; do not reuse a personal password. `SESSION_SECRET` is generated by Render.
4. Deploy and wait for the `/api/health` check to pass. Render will provide a public HTTPS URL.

**Storage note:** this starter Blueprint uses Render's free web-service plan, which does not provide a persistent disk. SQLite reports and uploaded photos may be lost when the service restarts or redeploys. For a real demo with durable reports, configure a persistent disk or migrate storage to a managed database/object store before collecting real public submissions. This app is a student demo and does not automatically send complaints to municipal authorities.
